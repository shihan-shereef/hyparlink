2. ARCHITECTURE OF THE ENVIRONMENT & DEPENDENCY SYSTEM
--------------------------------------------------------------------------------

A. DETECTION SERVICE (EnvironmentChecker)
   - Location: ai-composition-generator/src/system/environment-checker.ts
   - Features:
     * Node.js: Validates process.version >= 18.
     * npm: Validates npm --version >= 8.
     * FFmpeg: Resolves path dynamically prioritizing process.env.FFMPEG_PATH, PATH,
       and vendor bundle (/Applications/HyperFrames.app/.../vendor/ffmpeg/darwin-arm64).
       Validates H.264 video encoding and AAC audio encoding capabilities.
     * FFprobe: Dynamically locates and verifies executable.
     * HyperFrames: Inspects local node_modules/hyperframes/package.json for instant
       (0.05s) offline verification, with npx --prefer-offline fallback.
     * Storage: Performs read/write/delete checks and queries free disk space (df -k).
     * TTL Caching: Caches result for 30 seconds to prevent unnecessary subprocess
       spawns during rapid UI interaction.

B. BACKEND REST API ENDPOINT
   - Location: backend-echo/server.mjs
   - Routes:
     * GET /health/dependencies (and /api/health/dependencies)
       Returns structured JSON with dependency versions, codec status, and readiness.
       Supports ?recheck=true to bypass cache.
     * POST /health/dependencies/setup (and /api/health/dependencies/setup)
       Executes safe, whitelisted environment setup script (scripts/setup-environment.sh)
       and returns fresh dependency status.
     * Zero secret leakage: API keys, tokens, and internal credentials are never exposed.

C. PRE-FLIGHT READINESS ENFORCEMENT
   - Location:
     * ai-composition-generator/src/pipeline/generate-video.ts
     * backend-echo/server.mjs (/jobs/run)
   - Functionality:
     Before initiating AI composition synthesis or headless rendering, the pipeline
     queries EnvironmentChecker.checkEnvironment(). If renderingReady is false, the job
     is aborted immediately with an actionable error message and marked "failed" in Convex,
     preventing failed rendering jobs from appearing as successes.

D. DASHBOARD USER INTERFACE
   - Component: apps/app/src/components/dependency-status-card.tsx
   - Integrations:
     1. apps/app/src/app/[locale]/(dashboard)/settings/page.tsx
        Displays persistent "Video Rendering Environment" card showing Node.js, npm,
        FFmpeg, FFprobe, HyperFrames, and Storage statuses with "Recheck" and "Auto-Setup" buttons.
     2. apps/app/src/app/[locale]/(dashboard)/create-video/page.tsx
        Header features interactive "Rendering Environment Ready ✓" badge with pulse
        indicator that expands the DependencyStatusCard on demand.

E. DOCKER & LOCAL INSTALLATION WORKFLOWS
   - Local Setup: scripts/setup-environment.sh detects macOS vs Linux, installs or
     symlinks FFmpeg/FFprobe into ~/.local/bin, verifies H.264/AAC, and tests permissions.
   - Container Build: Dockerfile uses node:20-bookworm-slim, installs system ffmpeg
     and required font/graphics libraries, and pre-caches HyperFrames CLI 0.8.139.
