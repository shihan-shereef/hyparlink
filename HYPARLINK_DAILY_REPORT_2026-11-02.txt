PART 1: IN-VIDEO ARROWS, SPEARS, ILLUSTRATIONS & TEXT INTERACTION
--------------------------------------------------------------------------------
- User Issue:
  "the thing is that i dont get it the all video is created using the html but 
  still ama not able to select the other aros images and the some of the text 
  for the vido find it why and if it is a fixable ishue fixit"

- Root Cause Analysis:
  1. Spear / Arrow Physical Dimensions & CSS Rotation:
     In `styles.css`, decorative spear arrows (`.spear.left`, `.spear.right`) 
     are only 5px wide and rotated at 24° and -24°. When rendered on a 1920x1080 
     canvas scaled down to an ~800px display, the physical width was only ~2 pixels. 
     Clicking on or near the arrow missed the target and hit the background section, 
     triggering canvas deselection.
  2. Missing Container Types in `TEXT_CONTAINERS_QUERY`:
     Titles like "CHOLA" and "PANDYA" are marked up as:
     `<div style="position:absolute; left:8%; top:34%; font:clamp(20px,3vw,42px) Georgia; color:#e68b69;">CHOLA</div>`
     Because they lacked standard heading tags (h1-h6) or class names, the 
     editor's selector query (`TEXT_CONTAINERS_QUERY`) did not recognize them as 
     containers and failed to map them to canvas handles.
  3. Strict Time-Window Filtering:
     `visibleElements` previously discarded elements if the playhead was a fraction 
     of a second before or after scene boundaries, hiding overlay targets.

- Engineering Solutions Applied:
  1. Updated `TEXT_CONTAINERS_QUERY` in `ElementsCanvasOverlay.jsx`:
     Added `.spear, [class*='spear'], [class*='arrow'], .battleline, .rule, .map, svg, div[style*='font'], div[style*='position']`.
  2. Padded & Centered Hitbox Bounding Boxes in `getDynamicPlacement`:
     Elements narrower than 50px (such as spears and lines) now dynamically 
     receive an expanded bounding box of at least 70px width by 50px height, 
     centered directly over the physical element coordinate.
  3. Multi-Point Fuzzy Hit Probing in `onPointerDown`:
     Added an offset probe array (±15px, ±25px, ±35px) around click coordinates. 
     Clicks near thin or rotated lines lock onto the element cleanly rather than 
     falling through to the canvas background.
  4. Live DOM Visibility Checking:
     `visibleElements` now queries the iframe DOM's computed scene opacity and 
     visibility (`visibility !== "hidden"` and `opacity > 0.05`), ensuring any 
     currently rendered scene element has active canvas handles.
  5. Injected CSS Hitboxes in `backend-echo/server.mjs`:
     Added `::after` pseudo-element padding (-35px top/bottom, -45px left/right) 
     and hover dashed cyan outlines (`2px dashed rgba(56, 189, 248, 0.85)`) on 
     all spears, battlelines, and styled text.
  6. Comprehensive DOM Scanner in `App.jsx`:
     Updated `extractElementsFromProject` to catalog all spears, arrows, battlelines, 
     rules, maps, and styled `<div>` elements into the editor's reactive element state.

PART 2: NATIVE EDITOR RUNTIME CRASH FIX (`filter@[native code]`)
--------------------------------------------------------------------------------
- User Issue:
  Native editor displayed an unhandled JavaScript error on initial load:
  "Native Editor Error: filter@[native code]"

- Root Cause:
  Inside `ElementsCanvasOverlay.jsx`, line 312 checked `selectedId` instead of 
  the component's prop `selectedElementId`, causing a fatal ReferenceError during 
  array filtering in the production build.

- Engineering Solutions Applied:
  1. Updated the filter condition to:
     `selectedSet.has(el.id) || (selectedElementId && el.id === selectedElementId)`
  2. Executed a clean Vite production build (`npm run build`) in `scratch/ai-video-editor/`.
  3. Successfully emitted `editor-CVzpu2aF.js` (6.74 MB) and linked it in 
     `apps/app/public/native-editor/index.html`.
  4. Verified HTTP 200 OK delivery through both localhost and Cloudflare tunnel.
