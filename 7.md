## 4. Backend & Domain Service Implementation

### 1. Job Ingestion & Execution (`POST /jobs/run`)
When Convex dispatches a job:
```json
{
  "jobId": "job-123",
  "kind": "video.generate",
  "input": {
    "projectId": "proj-456",
    "prompt": "Create a 5-second 1080p landscape title card...",
    "duration": 5,
    "width": 1920,
    "height": 1080,
    "fps": 30
  }
}
```
The backend:
1. Responds immediately with `202 Accepted` (`{ accepted: true, jobId }`).
2. Dispatches intermediate progress webhooks to Convex (`type: "job.progress"`, `status: "generating"`, `status: "validating"`).
3. Invokes `VideoGenerationPipeline` from `ai-composition-generator`.
4. Dispatches final webhook (`type: "job.result"`) with full render metrics, video URL, and validation report.

### 2. Streaming Media Server (`GET /outputs/:filename`)
- Serves the generated MP4 with `Content-Type: video/mp4`.
- Supports HTTP 206 Partial Content range requests (`Range: bytes=0-...`) and HEAD requests for browser streaming.

## 5. Job Lifecycle & Webhook Flow

```
[1. User clicks Generate]
    │
    ▼
[2. Convex Mutation: api.projects.create]
    ├── Inserts project (status: "generating")
    ├── Inserts job (kind: "video.generate", status: "pending")
    └── Schedules internal.jobs.processJob
    │
    ▼
[3. Convex Action: processJob]
    ├── Patches job (status: "running")
    └── Calls POST ${BACKEND_BASE_URL}/jobs/run
    │
    ▼
[4. Backend: Executes Phase 5 Pipeline]
    ├── Posts webhook: type "job.progress", status "generating"
    ├── AI Generates HyperFrames code
    ├── Posts webhook: type "job.progress", status "validating"
    ├── HyperFrames Check validates timelines (auto-fix loop if needed)
    └── HyperFrames Render renders MP4 via Metal GPU
    │
    ▼
[5. Backend: Posts Webhook to Convex /backend/webhook]
    └── Payload: { type: "job.result", jobId, result: { videoUrl, duration, ... } }
    │
    ▼
[6. Convex Webhook Action]
    └── Runs internal.jobs.complete:
         ├── Patches job (status: "done")
         ├── Patches project (status: "completed", outputUrl: videoUrl, ...)
         └── Dispatches user notification
    │
    ▼
[7. Reactive Frontend UI Updates Automatically]
    └── Stepper reaches 100%, reveals "View Video" and player
```

## 7. Security Implementation

1. **Workspace Authorization**: All project and job operations require authenticated session (`getAuthUserId`) and verified workspace membership (`requireMember`).
2. **Multi-Tenant Scoping**: All queries filter strictly by `workspaceId` using indexed queries (`by_workspace`). A user from workspace A cannot access projects or videos from workspace B.
3. **Webhook Authentication**: Incoming webhooks validate the `x-webhook-secret` header against `process.env.BACKEND_WEBHOOK_SECRET`.
4. **Backend Service Authentication**: Direct proxy calls validate `x-service-key` against `process.env.BACKEND_SERVICE_KEY`.
5. **AI API Key Protection**: AI credentials (`AI_API_KEY`) remain strictly on the backend domain server and are never sent to or accessible by client browser bundles.
