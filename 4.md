# Prompt-to-Composition Pipeline & End-to-End Architecture
**Report #4** — Natural Language Prompting to Rendered Video

---

## 1. Executive Summary

This report analyzes how a natural-language prompt (e.g. *"Create a 30s product launch video for a cybersecurity SaaS with kinetic typography and enterprise server visuals"*) is translated into a valid, renderable HyperFrames composition (`index.html`, CSS, GSAP timelines, assets) before the rendering engine is invoked.

### Key Finding:
**HyperFrames already provides a complete, sophisticated Agentic Prompt-to-Composition Framework in this environment.** It is installed locally under `/Users/apple/.agents/skills/` (and mirrored in `~/.claude/skills/` and `~/.aider-desk/skills/`), which directly powers the installed **HyperFrames Desktop App** (`dev.hyperframes.desktop.plist`).

However, for a web-based **Convex Dashboard**, users submit prompts via a web UI rather than an interactive CLI agent. Therefore, the HyperFrames domain backend must wrap this agentic pipeline into an automated **Composition Generation Worker**.

## 2. Existing Prompt-to-Composition Implementation in this Environment

The environment contains an installed suite of 10 specialized workflows and domain skills:

### The Installed Skill Suite (`/Users/apple/.agents/skills/`)
1. **`hyperframes`** ([SKILL.md](file:///Users/apple/.agents/skills/hyperframes/SKILL.md)): Root router and intent layer.
   * `references/intent-interview.md`: Triage, must-haves, run-shape, and hand-off.
   * `references/brief-format.md`: Generates the structured `BRIEF.md` deliverable.
   * `references/production-loop.md`: Dependency chain: Blocks ➔ Audio/TTS ➔ Frames ➔ Assembly ➔ Transitions ➔ Captions ➔ Verify.
2. **Workflows**:
   * `/product-launch-video`: Website URL or script ➔ SaaS / promo video.
   * `/faceless-explainer`: Topic / notes ➔ 60–90s explainer.
   * `/motion-graphics`: Short (<10s) kinetic typography, counters, logo sting.
   * `/music-to-video`: Beat-synced visual montage.
   * `/embedded-captions` & `/talking-head-recut`: Captions and graphic overlays on existing video footage.
   * `/general-video`: Multi-scene custom montage.
3. **Core Authoring Skills**:
   * `hyperframes-core`: DOM structure, strict timing (`data-start`, `data-duration`), full-frame `.clip` layouts, `data-composition-variables`.
   * `hyperframes-animation`: GSAP timeline orchestration, `window.__timelines` registration, seek-safe animation rules.
   * `hyperframes-audio`: Audio mixing, TTS generation via local Kokoro-82M model (`npx hyperframes tts`), beat detection (`npx hyperframes beats`), and loudness normalization.
   * `hyperframes-registry`: Installs pre-built animation blocks (`touch-indicator`, `matrix-decode`, `code-snippet`, etc.) from HeyGen's block cache (`~/.hyperframes/cache/`).
   * `hyperframes-cli`: Linter, headless Chrome validator, previewer, and compiler.

## 3. How a Prompt Becomes a Valid HyperFrames Composition

HyperFrames follows a strict 5-stage generation pipeline:

```
[User Prompt]
      │
      ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 1. INTENT & BRIEF EXTRACTION (LLM)                                     │
│    Outputs BRIEF.md & STORYBOARD.md (Scenes, Pacing, Duration, Aspect) │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2. ASSETS & AUDIO STAGING                                              │
│    - TTS Voice generation via `npx hyperframes tts`                   │
│    - Block installation via `npx hyperframes add <block>`              │
│    - BGM audio bed carving & LUFS loudness leveling                   │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 3. HTML & GSAP TIMELINE AUTHORING                                      │
│    - Sub-compositions authored in `compositions/scene_NN.html`        │
│    - Root `index.html` orchestrating tracks, clips, and transitions    │
│    - GSAP timelines bound to `window.__timelines`                     │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 4. MECHANICAL VERIFICATION GATE                                        │
│    Run `npx hyperframes check` in headless Chrome:                     │
│    ✓ Timing integrity  ✓ No console JS errors  ✓ Asset paths valid    │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 5. READY FOR RENDER                                                    │
│    Invoke `npx hyperframes render` or `hyperframes cloud render`       │
└────────────────────────────────────────────────────────────────────────┘
```

### Composition Code Contract
A generated HyperFrames project consists of:
* **`index.html`**:
  ```html
  <!DOCTYPE html>
  <html>
    <head>
      <script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.12.5/gsap.min.js"></script>
      <style>
        .clip { position: absolute; inset: 0; width: 100%; height: 100%; }
      </style>
    </head>
    <body data-composition-duration="30" data-width="1920" data-height="1080">
      <!-- Scene 1: 0s to 5s -->
      <div class="clip" data-start="0" data-duration="5" id="scene-1">
        <h1 class="kinetic-title">Next Generation AI</h1>
      </div>
      <script>
        const tl = gsap.timeline({ paused: true });
        tl.from(".kinetic-title", { opacity: 0, y: 50, duration: 1 });
        window.__timelines = [tl];
      </script>
    </body>
  </html>
  ```
* **`hyperframes.json`**: Configures registry paths and auto-proxy video codecs.
* **`meta.json`**: Project metadata.

## 4. What Component Needs to Be Built for the Dashboard

Because this is a **headless, web-driven dashboard**, the web user will not be interacting with a terminal agent directly. 

We must implement a **Prompt-to-Composition Service** within the HyperFrames domain backend:

### Component Specification: `CompositionGenerator`
* **Input**:
  * `prompt`: Natural-language description from user.
  * `aspectRatio`: `16:9`, `9:16`, or `1:1`.
  * `targetDuration`: e.g. 15s, 30s, 60s.
  * `brandAssets`: Uploaded logos, images, or audio IDs from Convex `files` table.
* **Logic**:
  1. Calls LLM with the HyperFrames authoring system prompt (derived from `/Users/apple/.agents/skills/hyperframes-core/` and `hyperframes-animation/`).
  2. Generates the project folder under `.hyperframes-studio/<projectId>/`.
  3. Writes `index.html`, sub-compositions, and styles.
  4. Runs `npx hyperframes check --json`. If lint errors exist, performs automated self-healing.
  5. Once verification passes, calls `hyperframes render`.

## 5. Complete End-to-End Architecture

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. USER INTERFACE (Next.js Dashboard - apps/app)                            │
│    User types: "Create a 30s promo for Networkers Home with server racks"   │
│    Clicks [Generate Video] ➔ Calls Convex mutation `api.jobs.create`        │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. CONVEX CONTROL PLANE (packages/backend)                                  │
│    - Inserts job record (`kind: "prompt_to_video"`, `status: "pending"`)    │
│    - `processJob` action fires POST `${BACKEND_BASE_URL}/jobs/run`           │
│      carrying `x-service-key` and `x-user-id`                               │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 3. HYPERFRAMES BACKEND (Port 4000)                                          │
│    - Validates `x-service-key`, returns 202 Accepted to Convex              │
│    - Dispatches to `CompositionGenerator`:                                  │
│      a. LLM generates script, storyboard, and scene structure               │
│      b. Synthesizes voiceover (`npx hyperframes tts`)                       │
│      c. Generates `index.html` + GSAP seekable timeline                     │
│      d. Validates via `npx hyperframes check`                               │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 4. HYPERFRAMES RENDER PIPELINE                                              │
│    - Headless render: `npx hyperframes render --resolution 1080p`           │
│      (or HeyGen Cloud: `hyperframes cloud render --callback-url=...`)       │
│    - Encodes video to MP4 (1920x1080 @ 30fps) with synced stereo audio      │
│    - Extracts video thumbnail (`snapshot`)                                  │
│    - Uploads video to CDN / Convex Storage                                  │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 5. CONVEX WEBHOOK CALLBACK (http.ts)                                        │
│    - HyperFrames posts to `POST <CONVEX_SITE_URL>/backend/webhook`          │
│      Payload: { type: "job.result", jobId, result: { videoUrl, ... } }      │
│    - Convex marks job `status: "done"` & fires in-app notification          │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 6. REACTIVE DASHBOARD UI UPDATE                                             │
│    - `usePaginatedQuery(api.jobs.listPaged)` updates automatically          │
│    - Dashboard displays video preview player, timeline, and MP4 download   │
└─────────────────────────────────────────────────────────────────────────────┘
```
