C. HyperFrames Headless 1080p Renderer Optimization
--------------------------------------------------------------------------------
- Issue: 60-second 1080p video generation aborted with a command timeout:
  `Command failed: npx --yes hyperframes@0.8.139 render --resolution 1080p --format mp4 ...`
- Root Causes Identified:
  1. Low-Memory Profiling Throttle: Because total VM system RAM was 7,941 MB 
     (just below the 8,192 MB threshold), HyperFrames automatically activated 
     `lowMemoryMode: true`, skipped worker calibration, and pinned capture to 1 worker.
     At 1 worker, capturing 1,800 frames at 1080p took ~15-20 minutes, exceeding 
     the 10-minute child-process timeout.
  2. Uncompressed Image Assets: Wikimedia historical images were downloaded at raw 
     resolutions (up to 4000x3000, 3 MB+ per image). Loading multiple multi-megabyte 
     images simultaneously in headless Chromium during capture saturated CPU and memory.
- Solutions Applied:
  1. Forced multi-worker execution: Passed `--no-low-memory-mode --workers 4` to 
     the HyperFrames CLI invocation and set `PRODUCER_LOW_MEMORY_MODE: "false"`.
  2. Automated asset pre-compression: Updated `image-downloader.ts` to inspect image 
     dimensions via `ffprobe`. Any asset exceeding 1920px or 1.2 MB is automatically 
     downscaled to 1920x1080 and compressed to high-efficiency WebP/JPEG (~460 KB) 
     before being passed into the composition.
  3. Expanded timeout budget: Increased child-process execution timeout from 10m to 
     30m, ensuring uninterrupted high-bitrate SDR rendering.
  4. Verified output: Full 60s 1080p MP4 with multiplexed audio and GSAP animations 
     rendered cleanly in 5 minutes 28 seconds.

G. Independent Element Dragging & Coordinate Normalization
--------------------------------------------------------------------------------
- Issue: When users clicked to move an element, it was stuck or snapped back, or dragged 
  the entire card container rather than the individual clicked element.
- Root Causes Identified:
  1. Parent Wrapper Shadowing: HyperFrames assigns `data-hf-id` to both outer container 
     cards (e.g. `<div class="glass-card">`) and inner text elements (`<h1>`, `<p>`). 
     The extractor originally extracted outer containers, overlaying a giant hit-box 
     that absorbed all mouse clicks and blocked inner elements.
  2. Dynamic Placement Override: `getDynamicPlacement()` re-queried the iframe DOM 
     during dragging. Because elements in standard flow were governed by parent CSS 
     flex/grid layout, reading un-dragged flow coordinates continuously snapped the 
     dragged element back.
  3. Sub-Iframe Offset Calculation: Setting `position: absolute; left: ...px; top: ...px` 
     without subtracting `offsetParent.getBoundingClientRect()` added double offsets 
     in nested subcomposition iframes.
- Solutions Applied:
  1. Leaf-Only Extraction: Updated element extraction in `App.jsx` to detect if a 
     container contains child headings, paragraphs, buttons, or badges. If so, the 
     outer wrapper is skipped, guaranteeing that only individual, distinct leaf 
     elements receive interactive selection outlines.
  2. Independent Drag Priority: `ElementsCanvasOverlay.jsx` now prioritizes 
     `el.placement.x/y` whenever an element has moved (`hasMoved` or `isDragging`), 
     enabling 1:1 responsive cursor following.
  3. OffsetParent Subtraction: When an element is moved, `updateElement` calculates:
     `targetLeftPx = (pl.x / 100) * docW - pRect.left;`
     `targetTopPx = (pl.y / 100) * docH - pRect.top;`
     properly accounting for any parent container position.
  4. Layout Spacers: Dynamically inserts invisible layout spacers (`.hf-layout-spacer`) 
     matching the original element's dimensions into the parent flow, preventing 
     surrounding sibling elements from shifting or reflowing when the dragged 
     element transitions to `position: absolute`.

--------------------------------------------------------------------------------
H. Element Dimension Preservation & Anti-Reshaping Engine
--------------------------------------------------------------------------------
- Issue: User reported: "when i dragging the elements the shape is changing when i drag 
  the boxes or other elements rather than text it is resizing something is hiding and all".
- Root Causes Identified & Eliminated:
  1. Text Range Rect Clamping (`range.selectNodeContents`):
     In `ElementsCanvasOverlay.jsx`, `getDynamicPlacement()` previously created a DOM 
     Range selecting character contents inside elements. For cards, boxes, pills, 
     and buttons, this measured ONLY the inner text glyphs, discarding the element's 
     padding, border, and width (e.g. shrinking a 400x180 card to 120x24).
  2. Destructive `width: fit-content` Injection:
     In `App.jsx`, when saving or moving non-image elements, `widthStyle` was hardcoded to:
     `width: fit-content; max-width: 90%;`
     This forcibly overwrote the card's width in the HTML file, crushing multi-line text 
     into narrow columns and clipping container contents.
  3. Destructive Style Stripping in `cleanPos`:
     The `cleanPos` utility previously stripped `width`, `height`, `max-width`, and 
     `max-height` from existing element style attributes on disk.
  4. Artificial `+ 4` Dimension Drift:
     `ElementsCanvasOverlay.jsx` added `+ 4` to measured element width and height, 
     causing elements to drift by 4px on each move.
  5. Unlocked Height on Drag:
     `updateElement` only locked height for `img` and `svg`, leaving cards and boxes 
     with undefined heights when switching to `position: absolute`.
- Solutions Applied:
  1. True Element Bounding Box: Removed `range.selectNodeContents(targetEl)`. The overlay 
     now directly uses `targetEl.getBoundingClientRect()`, preserving all padding, 
     borders, and container geometry.
  2. Zero Artificial Drift: Removed `+ 4` expansion, aligning overlay bounds 1:1 with 
     the element.
  3. Locked Rendered Dimensions: In `updateElement` (live DOM), before applying 
     `position: absolute`, the engine inspects rendered `offsetWidth` and `offsetHeight` 
     and locks them in pixels (`box-sizing: border-box`).
  4. Protected HTML Files: Updated `cleanPos` to ONLY strip positioning styles 
     (`position`, `left`, `top`, `margin`, `transform`, `z-index`). Existing `width`, 
     `height`, `padding`, `background`, and `border` styles are 100% preserved.
  5. Strict Resizing Guard: `width` and `height` style adjustments are strictly 
     restricted to explicit resize actions (`changes.isResizing === true`). Pure drag 
     operations only modify `left` and `top`.
