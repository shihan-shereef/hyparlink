# HyperFrames Dashboard Architecture & Implementation Plan
**Report #1** — Inspection & Architecture Assessment

---

## 1. Executive Summary

This project is a high-performance **Turborepo monorepo** built with **Next.js 14 (App Router)**, **Convex (control plane database & real-time engine)**, and a **hybrid backend adapter**.

The repository is specifically structured as a **two-plane architecture**:
1. **Control Plane (Convex)**: Owns user identity, authentication, multi-tenant organizations/workspaces, role-based access control (RBAC), storage pointers, audit logs, notifications, and real-time dashboard UI state.
2. **Domain Plane (External Backend - HyperFrames)**: Owns the video production and rendering engine, frame composition pipeline, video encoding/FFmpeg workflows, GPU rendering, and core generative AI models.

This template is ideally suited to be transformed into the **HyperFrames User Dashboard**. The entire authentication, multi-tenancy, job dispatching, file handling, and API key management layers are already built and fully functional.

## 4. Authentication & Security Architecture

* **Engine**: `@convex-dev/auth` with Next.js edge middleware (`apps/app/src/middleware.ts`).
* **Authentication Providers**:
  1. **Magic Email OTP**: Passwordless login using 6-digit one-time codes sent via Resend or Mailpit SMTP.
  2. **Email + Password**: Full password flow with complexity verification (8+ chars, upper, lower, numbers), verification codes, and password reset flows.
  3. **Google OAuth**: Hooked up in `auth.ts`, ready to activate via `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET`.
* **Security & Tokens**:
  * **Brute-Force Protection**: 5 attempts per hour per email limit.
  * **JWKS Identity Provider**: Convex acts as an OIDC / JWKS identity provider. It signs RS256 JWTs (`iss=<site>`, `aud=convex`) published at `<site>/.well-known/jwks.json`.
  * **Session Management**: Full active session tracking (`authSessions` table) with single-session or "sign out everywhere" revocation.

## 5. Convex Database Schema & Function Capabilities

The database schema (`packages/backend/convex/schema.ts`) is strictly multi-tenant with workspace scoping:

* **`workspaces` & `members`**: Workspaces define the tenant boundary. Members have assigned roles (`owner`, `admin`, `member`) enforced by `requireMember` and `requireRole` guards.
* **`jobs`**: Asynchronous task queue with fields: `workspaceId`, `userId`, `kind`, `status`, `input`, `result`, `error`, `createdAt`, `updatedAt`.
* **`files`**: File metadata table linked to Convex's built-in file storage (`_storage`).
* **`events`**: Log table for inbound events streamed from the external backend via webhooks.
* **`usage` & `counters`**: High-performance $O(1)$ metric tracking (increments via `bump()`) for stats cards without scanning large tables.
* **`apiKeys`**: Programmatic API keys (`sk_...`) stored as SHA-256 hashes, with verification via `/api/verify-key`.
* **`auditLogs` & `notifications`**: Action audit trails and real-time user notifications.

## 6. API Integration Points (Connecting HyperFrames)

The template provides **three distinct connection paths** between the client/Convex and an external backend (demonstrated in `backend-echo/server.mjs` and `apps/app/src/lib/backend-client.ts`):

```
                                  ┌────────────────────────┐
                                  │ Next.js App (Browser)  │
                                  └────┬──────────────┬────┘
                                       │              │
                   Direct Path (JWT)   │              │ Proxy Path
                                       ▼              ▼
┌──────────────────────────────────────────┐    ┌──────────────────────────┐
│           HyperFrames Backend            │    │      Convex Backend      │
│ (Video Rendering, AI Engine, Compositor) │    │      (Control Plane)     │
└───────────────┬──────────────────────────┘    └─────────────┬────────────┘
                │                                             │
                │ Webhook (/backend/webhook)                  │
                └─────────────────────────────────────────────┘
```

### Path 1: Direct Client Path (Browser ➔ HyperFrames API)
* **Mechanism**: Handled via `useDirectBackend()` in `apps/app/src/lib/backend-client.ts`. The browser calls the HyperFrames API directly with `Authorization: Bearer <Convex_JWT>`.
* **Authentication**: HyperFrames validates the token against Convex's public JWKS endpoint:
  ```javascript
  const JWKS = createRemoteJWKSet(new URL(`${CONVEX_SITE_URL}/.well-known/jwks.json`));
  const { payload } = await jwtVerify(token, JWKS, { audience: "convex" });
  ```
* **Best used for**: High-throughput / low-latency operations:
  * Live frame rendering / canvas preview.
  * Timeline scrubbing and real-time playback streaming.
  * Direct file uploads to video storage/S3/R2 (bypassing Convex size limits).

### Path 2: Proxy Path (Browser ➔ Convex Action ➔ HyperFrames API)
* **Mechanism**: Handled via `useProxyBackend()` calling the Convex action `api.backend.callBackend`.
* **Authentication**: Convex attaches `x-service-key: <BACKEND_SERVICE_KEY>` and `x-user-id: <userId>` to the request to `BACKEND_BASE_URL`.
* **Best used for**: Server-authenticated operations:
  * Dispatching heavy video render jobs.
  * Applying team-level settings or billing-gated features before calling HyperFrames.

### Path 3: Webhook / Callback Path (HyperFrames API ➔ Convex)
* **Mechanism**: HyperFrames posts to `POST <CONVEX_SITE_URL>/backend/webhook` with header `x-webhook-secret: <BACKEND_WEBHOOK_SECRET>`.
* **Job Completion**:
  ```json
  {
    "type": "job.result",
    "jobId": "jd7...",
    "result": {
      "videoUrl": "https://cdn.hyperframes.io/renders/export-1080p.mp4",
      "thumbnailUrl": "https://cdn.hyperframes.io/renders/thumb.jpg",
      "duration": 45.2,
      "format": "mp4"
    }
  }
  ```
  Convex automatically updates the job status to `done` and triggers an in-app notification. The browser UI reactively displays the rendered video without refreshing.

## 8. Recommended Implementation Plan for HyperFrames Dashboard

### Phase 1: Rebranding & HyperFrames Configuration
* Update `project.config.ts` from `"myos"` to `"HyperFrames"`.
* Replace `/logo.png` and favicon with HyperFrames branding.
* Configure `BACKEND_BASE_URL` and `NEXT_PUBLIC_BACKEND_URL` in environment files.

### Phase 2: Schema Expansion in Convex
Add video production primitives to `packages/backend/convex/schema.ts`:
1. **`projects`**: Video compositions / timelines (title, aspect ratio, fps, resolution, scene data, thumbnail, status).
2. **`templates`**: Ready-to-use video project presets and compositions.
3. **`renders` / Extend `jobs`**: Extend the jobs table or create dedicated render job indexes tracking resolution, duration, progress percentage (0–100%), and output CDN URLs.

### Phase 3: Video Projects Management (Dashboard UI)
* Create `apps/app/src/app/[locale]/(dashboard)/projects`:
  * Project grid with video thumbnails, duration badges, and status.
  * "New Video Project" creation modal (aspect ratios: 16:9, 9:16, 1:1, 4:5).
  * Project duplicate, rename, archive, and delete functions.

### Phase 4: Video Render & Export Hub
* Upgrade `/(dashboard)/jobs` into the **HyperFrames Render Hub**:
  * Live progress bars for active rendering jobs.
  * In-dashboard video player modal for previewing finished exports.
  * Download button, copy share link, and export logs.

### Phase 5: Media & Asset Library
* Customize `/(dashboard)/files` to be video-centric:
  * Filter by asset types: Video clips, Audio/Music, Images, Fonts, Subtitles.
  * Video asset preview popovers and duration/resolution metadata tags.

### Phase 6: HyperFrames Backend API Integration
* Implement the JWKS token validator in the HyperFrames API for the direct path.
* Wire the HyperFrames render worker completion hook to Convex `/backend/webhook`.
* Test end-to-end: Create Project ➔ Configure Video ➔ Render ➔ Live Progress in Dashboard ➔ Playback.
