## 2. HyperFrames Backend / API Specifications

HyperFrames operates across **three backend modalities**:

### Modality A: The HeyGen Cloud Render API

* **Base URL**: `https://api.heygen.com/v1` (with asset staging at `https://hyperframes.heygen.com`).
* **Authentication**: HeyGen API Token (`HEYGEN_API_KEY` or `npx hyperframes auth`).

#### Endpoints & CLI Mapping:
1. **Submit Render**:
   * CLI: `hyperframes cloud render [options] [projectDir]`
   * Endpoint: `POST /v1/hyperframes/renders`
   * **Request Parameters**:
     ```json
     {
       "composition": "index.html",
       "fps": 30,
       "quality": "standard",
       "format": "mp4",
       "resolution": "1080p",
       "aspectRatio": "16:9",
       "variables": {
         "title": "Networkers Home Commercial",
         "themeColor": "#0066FF"
       },
       "callbackUrl": "https://<convex-site-url>/backend/webhook",
       "callbackId": "<convex-job-id>",
       "wait": false
     }
     ```
   * **Submission Response** (Fire-and-forget / `--no-wait --json`):
     ```json
     {
       "render_id": "hr_9b8f2a1c0d4e",
       "status": "queued",
       "created_at": "2026-10-08T10:20:00Z",
       "aspect_ratio": "16:9",
       "resolution": "1080p"
     }
     ```
2. **Poll Status / Detail**:
   * CLI: `hyperframes cloud get <render_id> --json`
   * Endpoint: `GET /v1/hyperframes/renders/:renderId`
   * **Status Response**:
     ```json
     {
       "render_id": "hr_9b8f2a1c0d4e",
       "status": "processing",
       "progress": 68.5,
       "current_frame": 1233,
       "total_frames": 1800
     }
     ```
3. **Completion Webhook Payload** (Fired to `callbackUrl`):
   ```json
   {
     "type": "job.result",
     "jobId": "<callbackId-passed-from-convex>",
     "render_id": "hr_9b8f2a1c0d4e",
     "status": "completed",
     "result": {
       "videoUrl": "https://cdn.hyperframes.io/renders/hr_9b8f2a1c0d4e/output.mp4",
       "thumbnailUrl": "https://cdn.hyperframes.io/renders/hr_9b8f2a1c0d4e/thumb.jpg",
       "duration": 62.0,
       "fps": 30,
       "resolution": "1920x1080",
       "sizeBytes": 27931321
     }
   }
   ```

### Modality B: Local Headless Render Engine & Service

* **Execution**: Run on a dedicated rendering host, worker process, or container.
* **Command**: `npx hyperframes render [projectDir] --output out.mp4 --resolution 1080p --json`
* **Request Input**:
  * Project source directory (containing `index.html`, `hyperframes.json`, `assets/`, `compositions/`).
  * Dynamic variables: `--variables '{"key":"value"}'` or `--variables-file=vars.json`.
  * Presets: `--resolution` (`1080p`, `4k`, `portrait`, `square`), `--format` (`mp4`, `webm`, `mov`).
* **Output Handling**: Emits binary MP4/WebM to disk, which is then uploaded to Convex `_storage` or S3/Cloudflare R2, returning the persistent URL.

---

### Modality C: Studio Preview Service (Port 3002)

* **Command**: `npx hyperframes preview --port 3002 --background --no-open`
* **Direct Path Role**:
  * Serves a live, frame-accurate interactive canvas player at `http://localhost:3002`.
  * Enables timeline scrubbing, element inspection, dynamic variable testing, and live preview inside an iframe on the user dashboard.

## 4. Exact Integration Flow with Convex

### Step 1: User Initiates Video Export from Dashboard
1. The user configures video settings (e.g. 1080p, 60fps, MP4, title variable) in the dashboard.
2. Next.js dashboard calls Convex mutation:
   ```ts
   await createJob({
     workspaceId,
     kind: "video_render",
     input: {
       projectId,
       resolution: "1080p",
       fps: 30,
       format: "mp4",
       variables: { title: "Company Presentation" }
     }
   });
   ```
3. Convex inserts row into `jobs` table (`status: "pending"`), updates workspace counters, and triggers `ctx.scheduler.runAfter(0, internal.jobs.processJob, { jobId })`.

### Step 2: Convex Proxies to HyperFrames Backend
1. Convex action `internal.jobs.processJob` executes:
   * Sets job status to `"running"`.
   * Sends `POST ${BACKEND_BASE_URL}/jobs/run`:
     ```http
     POST /jobs/run HTTP/1.1
     Host: localhost:4000
     Content-Type: application/json
     x-service-key: <BACKEND_SERVICE_KEY>
     x-user-id: <Convex_UserId>

     {
       "jobId": "jd72b4...",
       "kind": "video_render",
       "input": { ... }
     }
     ```

### Step 3: HyperFrames Executes Render
1. The HyperFrames Backend verifies `x-service-key`.
2. It returns `202 Accepted` to Convex immediately (`{ accepted: true, jobId }`).
3. The HyperFrames Backend delegates to the render pipeline:
   * **Cloud Route**: Calls HeyGen Cloud API passing `--callback-url` pointing to Convex `/backend/webhook` with `--callback-id = jobId`.
   * **Local / Worker Route**: Runs headless render (`npx hyperframes render ...`), generates `output.mp4`, uploads to storage, and prepares the result payload.

### Step 4: HyperFrames Posts Result to Convex Webhook
1. When rendering finishes, HyperFrames dispatches an HTTP POST to the Convex webhook endpoint:
   ```http
   POST /backend/webhook HTTP/1.1
   Host: 10.1.30.14:3211
   Content-Type: application/json
   x-webhook-secret: <BACKEND_WEBHOOK_SECRET>

   {
     "type": "job.result",
     "jobId": "jd72b4...",
     "result": {
       "videoUrl": "https://storage.hyperframes.io/renders/export-1080p.mp4",
       "thumbnailUrl": "https://storage.hyperframes.io/renders/thumb.jpg",
       "duration": 62.0,
       "resolution": "1920x1080",
       "format": "mp4",
       "sizeBytes": 27931321
     }
   }
   ```
2. Convex's `http.ts` validates `x-webhook-secret`, invokes `internal.jobs.complete`, patches the job status to `"done"`, decrements `openJobs`, and triggers an in-app notification.
3. The dashboard UI reactively updates via Convex live subscription without requiring page refresh.

## 5. Required Environment Variables

To bind Convex to the real HyperFrames backend:

### In Convex Deployment (`packages/backend`):
* `BACKEND_BASE_URL`: URL of the HyperFrames service (e.g. `http://localhost:4000` or production URL).
* `BACKEND_SERVICE_KEY`: Cryptographic shared secret authorizing Convex ➔ HyperFrames proxy calls.
* `BACKEND_WEBHOOK_SECRET`: Shared secret authorizing HyperFrames ➔ Convex webhook callbacks.
* `CONVEX_SITE_URL`: Base HTTP actions URL (e.g. `http://localhost:3211` or domain), used by HyperFrames to fetch JWKS and post webhooks.

### In Next.js Dashboard Client (`apps/app`):
* `NEXT_PUBLIC_CONVEX_URL`: Active Convex deployment URL (WebSocket reactive queries).
* `NEXT_PUBLIC_BACKEND_URL`: Public HyperFrames API / Studio URL (for direct canvas preview and JWKS-authenticated reads).

### In HyperFrames Service:
* `PORT`: `4000` (listening port).
* `SERVICE_KEY`: Matches `BACKEND_SERVICE_KEY`.
* `WEBHOOK_SECRET`: Matches `BACKEND_WEBHOOK_SECRET`.
* `CONVEX_SITE_URL`: Matches Convex HTTP actions URL.
* `CONVEX_AUDIENCE`: `"convex"` (for verifying direct client JWTs against JWKS).
* `HEYGEN_API_KEY`: (Optional) Required only if utilizing the HeyGen cloud rendering cluster.
