2. ROOT CAUSE INVESTIGATIONS & DETAILED DIAGNOSTICS
================================================================================

A. Issue: "No Changes Visible on Frontend After Editing Code"
   - Symptom: Modifications to `create-video/page.tsx` were saved in the repository,
     yet the browser displayed stale cards from earlier sessions.
   - Investigation:
     * Checked active process list: `bun run --filter @v1/app start -p 3000`.
     * `next start` serves the pre-compiled static `.next` artifact generated at
       10:27 AM. Unlike `next dev`, production mode does not poll or watch `.tsx` files.
   - Resolution:
     * Ran full production compilation via `bun run --filter @v1/app build`.
     * Build completed in 40.93s with zero TypeScript or lint errors.
     * Terminated stale process on port 3000 and launched the updated production server.
     * Verified HTTP 200 responses across all primary routes.

B. Issue: "Newly Created Videos Not Showing in Projects Side"
   - Symptom: Users creating videos or navigating to `/projects` encountered
     "No video projects yet", despite successful generation runs.
   - Investigation:
     * Queried Convex database directly across all workspaces via ConvexHttpClient:
       - Workspace 1 (`mh7eadmg10g11yqwbjtyc41yjs8fxx17`): 60 projects (all video runs).
       - Workspace 2 (`mh7fe9eyh6bvkh008p5aa2ne6s8fyegg`): 1 project.
       - Workspace 3 (`mh7efrm92meas1m268g0nv4zhn8g3vw3`): 0 projects.
     * All three workspaces were created with `name: "Personal"` and `role: "owner"`.
     * The sidebar dropdown rendered:
       - `Personal (owner)`
       - `Personal (owner)`
       - `Personal (owner)`
     * If `localStorage` had Workspace 2 or 3 active, `/projects` queried that empty
       workspace, hiding all 60 projects and newly rendered videos.
   - Resolution:
     * Updated `sidebar.tsx` to explicitly label the primary workspace:
       `Personal ★ (Primary - 60 Videos)`.
     * Updated `projects/page.tsx` to automatically fallback to the primary workspace
       if `current` is null or uninitialized.
     * Added a one-click auto-switch button in the empty state:
       "Switch to Primary Workspace (60 Videos)".

C. Direct HTML Video Creation in HyperFrames (Bypassing LLMs)
   - Inquiry: If raw HTML code is provided to HyperFrames, can it render directly
     without calling Ollima/LLMs?
   - Investigation of `ai-composition-generator/src/hyperframes/renderer.ts`:
     * `Renderer.render(options)` executes:
       `npx hyperframes@0.8.139 render --format mp4 -o output.mp4`
     * HyperFrames is a deterministic Chromium + FFmpeg timeline compiler.
     * It parses `index.html`, steps through the GSAP / CSS keyframe timeline at
       exact delta intervals (e.g. 1/30s or 1/60s), snapshots the frames, and pipes
       them directly into FFmpeg H.264/AAC encoding.
     * The LLM is NEVER called during compilation or rendering. The LLM is only an
       optional text-to-code translator used when a user writes a natural language prompt.
   - Implementation:
     * Live Editor (`/editor/[projectId]`): Users can click the "Source Code" tab,
       paste custom HTML into `index.html`, save, and click "Re-render Video".
       The video is compiled directly from the pasted HTML with zero AI calls.
