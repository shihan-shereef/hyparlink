       `✗ FFprobe not found: FFprobe is required to probe media assets`

       frontend progress bar spinning forever at 60%.

3. OLLASYNC TESTING & QA DEFECT REPORT (FROM USER PERSPECTIVE)
================================================================================
During testing of the Ollasync screen and cloud recording feature, two major timer 
defects were identified from the user's operational workflow. Below is the detailed 
testing report, impact assessment, and technical remediation roadmap.

--------------------------------------------------------------------------------
DEFECT 1: Timer Badge Fails to Freeze When Recording is Paused (Wall-Clock Drift)
--------------------------------------------------------------------------------
- Severity: High (User Experience & Usability)
- Component: Ollasync Recording Control Bar / Timer Badge
- User Test Scenario:
  1. User starts a screen / webcam recording session.
  2. Recording progresses normally up to 03:00 (3 minutes).
  3. User presses the "Pause" button on the recording controls.
  4. User waits for 30 seconds while the recording is in paused state.
  5. User clicks "Resume" to continue recording.
- Actual Behavior:
  * The timer badge immediately resumes displaying "03:30" (3 minutes and 30 seconds).
  * The timer counted the 30 seconds of paused idle time as part of the recorded duration.
- Expected Behavior:
  * When paused at 03:00, the timer badge MUST freeze display at "03:00".
  * When resumed 30 seconds later, the timer MUST continue from "03:00", then "03:01", 
    "03:02", etc., strictly reflecting the actual active video recording duration.
- Technical Root Cause:
  * The timer implementation calculates elapsed duration using a direct wall-clock delta:
      `elapsedTime = Date.now() - recordingStartTime;`
  * When paused, the component stops updating state or video track ingestion, but it 
    does not pause or accumulate the total paused duration.
  * Upon resuming, `Date.now() - recordingStartTime` includes the 30 seconds spent in pause.
- Recommended Fix:
  * Implement an accumulated active time tracker:
      - On pause: record `pauseTimestamp = Date.now()`.
      - On resume: calculate `totalPausedTime += (Date.now() - pauseTimestamp)`.
      - Calculate active recording time as:
          `activeElapsed = (Date.now() - recordingStartTime) - totalPausedTime;`
      - Ensure the formatted badge display uses `activeElapsed`.

--------------------------------------------------------------------------------
DEFECT 2: Cloud Recording Stop & Restart Timer Drift (Failure to Reset to 00:00)
--------------------------------------------------------------------------------
- Severity: Critical (Data Integrity & Session Isolation)
- Component: Ollasync Cloud Recording Session Manager / Timer Badge
- User Test Scenario:
  1. User starts a cloud recording session.
  2. Recording runs up to 04:00 (4 minutes).
  3. User presses the "Stop Recording" button to conclude the cloud recording.
  4. The recording stops and upload / processing initiates.
  5. User waits 30 seconds and clicks "Start Recording" to begin an entirely new recording.
- Actual Behavior:
  * The timer badge starts displaying "04:30" instead of starting from "00:00".
  * The new recording inherits the previous session's duration plus the 30-second interval between sessions.
- Expected Behavior:
  * When a cloud recording session is stopped, the timer state and session context MUST 
    be completely terminated and reset to zero.
  * When a new recording starts, the timer badge MUST start from "00:00" (0 seconds) 
    and increment normally ("00:01", "00:02", etc.).
- Technical Root Cause:
  * The component or global recorder store does not reset `recordingStartTime`, 
    `elapsedTime`, or interval timers when the user clicks "Stop".
  * Calling "Start Recording" a second time detects an existing `startTime` anchor from 
    the previous session or fails to clear the prior timer handle, resulting in continuous 
    cumulative duration display across distinct video recordings.
- Recommended Fix:
  * In the `stopRecording()` handler:
      - Explicitly invoke `clearInterval(timerIntervalHandle)`.
      - Reset `recordingStartTime = null`.
      - Reset `totalPausedTime = 0`.
      - Reset `elapsedSeconds = 0`.
      - Update UI timer badge state explicitly to `"00:00"`.
  * In the `startRecording()` handler:
      - Enforce a clean state check: `recordingStartTime = Date.now()`.
      - Initialize fresh timer interval starting strictly from 0 seconds.
