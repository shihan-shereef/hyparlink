--------------------------------------------------------------------------------
PART 1: TIMELINE SCRUBBING & BIDIRECTIONAL PLAYHEAD CONTROL
--------------------------------------------------------------------------------
- User Issue:
  "THE VIDOE IS PLAING ITS OWN AM ONT ABLE TO CONTROL IT USING THE TIMELINE."
- Root Cause:
  The composition preview iframe was rendering an unpaused video/GSAP timeline 
  that looped automatically without syncing with the React editor's timeline clock.
- Engineering Solution:
  1. In `scratch/ai-video-editor/src/App.jsx`, implemented bidirectional postMessage 
     and direct iframe DOM control (`postMessage({ type: "SEEK_COMPOSITION", time })`).
  2. In `backend-echo/server.mjs`, injected a runtime composer script into 
     `/editor/project/:projectId/raw/index.html` that captures GSAP timelines and 
     all `<video>` elements, binding play, pause, and seek events deterministically.
  3. When scrubbing the editor playhead, the live composition canvas seeks to the 
     exact frame synchronously without drift.

--------------------------------------------------------------------------------
PART 2: IN-VIDEO TEXT EDITING (EDITING REAL VIDEO TEXT INSTEAD OF DEMO TEXT)
--------------------------------------------------------------------------------
- User Issue:
  "IN THE VIDO U CAN SEE THE VIOE TEXT WHICH IS THERE IN THE VIDOE SHOWES THE 
  GODES OWN CARTY I NED THAT TECT TO BE EDITED IN SIE T THE VIDO BUT INSTED OF 
  THAT THE VIDOE EDITER ADDE AND ANOTHER TELX IN THE CENTER... I NEED TO EDIT 
  THE TEXT INSIDE THE VIDEO NOT THE DEMO TEXT."
- Root Cause:
  The editor previously generated mock text elements (`el-main-title`, etc.) 
  in the middle of the screen rather than reading the actual HTML composition DOM 
  elements rendered inside the iframe.
- Engineering Solution:
  1. Disabled automatic generation of fake placeholder captions and subtitle tracks.
  2. Injected `attachElementPicker` into composition iframes via `server.mjs`:
     - Listens for clicks on real headlines, titles, subtitles, kickers, pills, 
       and text elements inside the video.
     - Emits `HYPERLINK_ELEMENT_CLICKED` with the exact DOM ID, text, bounding 
       box, and computed typography styles.
  3. Clicking any text inside the video (such as "Kerala — God's Own Country") 
     selects that exact element and allows the user to edit its wording, color, 
     and typography directly.
  4. Changes are persisted in real time to the project files via 
     `POST /editor/project/:projectId/save`.

--------------------------------------------------------------------------------
PART 3: TIMELINE THUMBNAILS & DYNAMIC FILTER PREVIEW TILES
--------------------------------------------------------------------------------
- User Issue:
  "GIVE THE INMAGES OF THE TIME LINE BASIDE ON THE VIDOE AND GIVE THE IMAGES 
  FOR THE Filters AS WELL BUT DONOT EFFACT THE OTER PART OF THE WEB."
- Root Cause:
  1. The visual segment thumbnail was pointing to `/raw/index.html`. Browsers 
     cannot render an HTML document inside an `<img>` tag, causing a broken `[?]` icon.
  2. Filter card previews in `panels.jsx` were also reading `/raw/index.html` 
     as their thumbnail source, resulting in blank/broken preview cards.
- Engineering Solution:
  1. Updated `TimelineThumbnails.jsx`:
     - Added detection for composition assets.
     - Configured a cyclical carousel through real scene asset artwork images 
       (`kerala-intro.jpg`, `kerala-coast.jpg`, `kerala-mountains.jpg`, 
       `kerala-backwaters.jpg`, `kerala-culture.jpg`).
  2. Updated `getSegmentFilterPreview()` in `panels.jsx`:
     - Filtered out any URL ending with `.html`.
     - Provided valid poster thumbnails for each segment.
     - All filter cards (Original, Cool Clean, Film Vignette, Bright Portrait, 
       Clarity, Soft Glow, Moody Teal) now display live image thumbnails with 
       their corresponding CSS color grades.

--------------------------------------------------------------------------------
PART 4: RESOLVED {"error":"Project not found"} FOR ALL NON-LONDON VIDEOS
--------------------------------------------------------------------------------
- User Issue:
  "IT IS NOW WORKNG BUT ONLY AM ABOE TO OPAN THE LENDON VIDOE AND EDIT IT BUT 
  OTHER VIDEO SHOWES THIS {\"error\":\"Project not found\"}"
- Root Cause:
  1. London (`default_reference_video_2`) was matched via a hardcoded alias.
  2. Non-London videos (including Karnataka Coorg and user-generated videos) 
     are queried by their 32-character Convex document IDs (e.g., 
     `m57372k27qxvfy1z6zzrh37yrh8gs7aj`, `m57fnpy...`, `m574nfx...`).
  3. `backend-echo/server.mjs` only loaded the root `.env` file, leaving 
     `NEXT_PUBLIC_CONVEX_URL` undefined. It defaulted to `http://127.0.0.1:3210`, 
     which was refused locally (`ECONNREFUSED` / `fetch failed`).
  4. When Convex query failed, `resolveProjectDir` returned `null`, returning 
     HTTP 404 with `{"error":"Project not found"}` into the iframe canvas.
  5. Furthermore, relative directory paths in `project-map.json` caused 
     `!targetFile.startsWith(resolved.dir)` path-traversal false positives (HTTP 403).
- Engineering Solution:
  1. Multi-Env Loading (`backend-echo/server.mjs`):
     - Added robust loading and line-by-line fallback parsing of `apps/app/.env.local`, 
       `apps/app/.env`, `.env`, and `packages/backend/.env`.
  2. Convex Candidate Fallback Endpoints:
     - Configured `CANDIDATE_CONVEX_URLS`:
       * `process.env.CONVEX_URL`
       * `process.env.NEXT_PUBLIC_CONVEX_URL`
       * `https://communicate-ecommerce-advancement-subscription.trycloudflare.com`
       * `http://10.70.70.43:3210`
       * `http://127.0.0.1:3210`
  3. Direct Karnataka Coorg Mapping:
     - Mapped `m57372k27qxvfy1z6zzrh37yrh8gs7aj` and `default_reference_video` 
       directly to `job-job_code_1792219404621_iizjt`.
  4. Path Normalization:
     - Wrapped all directory resolutions with `path.resolve()` so path traversal 
       checks compare absolute canonical paths.
  5. Automatic Composition Scaffolding Fallback:
     - If an unseeded project ID is ever requested, the backend automatically 
       bootstraps `project-${projectId}` with valid HyperFrames HTML and metadata, 
       ensuring the canvas preview NEVER returns 404.
  6. Synced Generated Projects:
     - Synchronized generated composition directories between VM and local so 
       both environments have all assets.
